# Разработка микросервисов на FastAPI

> От первого эндпоинта до готового контейнеризированного сервиса

Практический вебинар для студентов модуля 5. Мы создаём **Anomaly Registry API** — сервис «Бюро аномалий», в котором регистрируют странные происшествия: телепортирующихся капибар, предсказывающие будущее кофейные автоматы и принтеры с документами из следующей недели.

Каждая стадия — полностью самостоятельный проект. Можно последовательно наблюдать развитие одного HTTP API или открыть нужный каталог отдельно.

[Открыть презентацию в Google Slides](https://docs.google.com/presentation/d/19qpQ4e_TmNzjH2DO1sGW6vIEp00RPdS8NxWnhCsCr-0)

## Ожидаемый результат

После вебинара студент сможет:

- создать небольшой CRUD API на FastAPI;
- описать и валидировать данные через Pydantic;
- сохранить данные в SQLite;
- работать с SQLAlchemy и применять миграции Alembic;
- запустить сервис в Docker;
- понимать место такого сервиса в микросервисной системе.

## Что понадобится

- Git;
- Python 3.12 или новее;
- [uv](https://docs.astral.sh/uv/);
- Docker с поддержкой Docker Compose для финальной стадии.

## Локальный запуск

Перейдите в каталог выбранной стадии. Для стадий `00`–`04`:

```bash
uv sync
uv run fastapi dev app/main.py
```

Начиная со стадии `05-alembic`, перед первым запуском примените миграции:

```bash
uv sync
uv run alembic upgrade head
uv run fastapi dev app/main.py
```

Приложение доступно по адресу [http://127.0.0.1:8000](http://127.0.0.1:8000), интерактивная документация — по адресу [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

## Запуск финальной версии в Docker

```bash
cd fastapi-microservices/06-docker-final
docker compose up --build
```

Контейнер применяет миграции автоматически. SQLite-файл хранится в Docker volume, поэтому данные сохраняются после перезапуска. Остановить сервис без удаления данных:

```bash
docker compose down
```

## API финальной версии

| Метод и путь | Назначение | Успешный статус |
| --- | --- | --- |
| `GET /` | Информация о сервисе | `200 OK` |
| `GET /health` | Проверка состояния | `200 OK` |
| `POST /incidents` | Зарегистрировать происшествие | `201 Created` |
| `GET /incidents` | Получить и отфильтровать список | `200 OK` |
| `GET /incidents/{incident_id}` | Получить происшествие по ID | `200 OK` |
| `PATCH /incidents/{incident_id}` | Частично обновить происшествие | `200 OK` |
| `DELETE /incidents/{incident_id}` | Удалить происшествие | `204 No Content` |

Доступные фильтры можно сочетать:

```text
GET /incidents?status=new
GET /incidents?category=creature
GET /incidents?danger_level=5
```

Отсутствующая запись возвращает `404 Not Found`, а данные, не прошедшие Pydantic-валидацию, — стандартный ответ FastAPI `422 Unprocessable Entity`.

## Модель происшествия

Категории: `space`, `time`, `creature`, `technology`, `unknown`.

Статусы: `new`, `investigating`, `resolved`.

Пример создания:

```json
{
  "title": "Капибара телепортируется между переговорками",
  "description": "Исчезает у доски и появляется возле кофемашины",
  "category": "creature",
  "danger_level": 4
}
```

Ответ сервиса:

```json
{
  "id": 1,
  "title": "Капибара телепортируется между переговорками",
  "description": "Исчезает у доски и появляется возле кофемашины",
  "category": "creature",
  "danger_level": 4,
  "status": "new"
}
```

Частичное обновление:

```json
{
  "status": "investigating"
}
```

## Почему это ещё не микросервисная система

На вебинаре мы создаём один самостоятельный, контейнеризированный сервис с чётким HTTP-контрактом. Он **может стать** частью микросервисной архитектуры, но один FastAPI-сервис в Docker сам по себе такую архитектуру не образует.

Возможное развитие системы:

```text
Incident Service
├── Agent Service
├── Notification Service
└── Analytics Service
```

HTTP подходит для взаимодействия, когда ответ другого сервиса нужен прямо сейчас. Для асинхронных событий — например, «происшествие зарегистрировано» — обычно подходит брокер сообщений. Kafka и RabbitMQ намеренно не входят в этот воркшоп: здесь важнее пройти весь путь одного сервиса от эндпоинта до контейнера, не скрывая основы за инфраструктурой.

## Бонусная часть

`07-tests-bonus` — резерв на случай, если на вебинаре останется время. В ней финальный HTTP-контракт проверяется через `pytest` и `TestClient`, а рабочая SQLite-база не используется.
