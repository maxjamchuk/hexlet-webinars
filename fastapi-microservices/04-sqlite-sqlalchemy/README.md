# Стадия 04: SQLite и SQLAlchemy

## Что изучаем

Сохраняем происшествия в SQLite через синхронный SQLAlchemy 2.x и получаем `Session` через `Depends`.

## Что изменилось

По сравнению с `03-crud-in-memory` данные переживают перезапуск. Модули базы, ORM-модели и HTTP-схем разделены. Для самостоятельного запуска таблица создаётся через `Base.metadata.create_all()` — это простой учебный вариант, который на следующей стадии заменят миграции.

## Установка и запуск

```bash
uv sync
uv run fastapi dev app/main.py
```

## Что проверить

Создайте запись через `/docs`, перезапустите приложение и убедитесь, что запись сохранилась в `incidents.db`.

| Метод и путь | Назначение |
| --- | --- |
| `GET /`, `GET /health` | Информация и проверка состояния |
| `POST /incidents` | Создать запись |
| `GET /incidents` | Список и фильтры `status`, `category`, `danger_level` |
| `GET /incidents/{incident_id}` | Получить запись |
| `PATCH /incidents/{incident_id}` | Частично обновить запись |
| `DELETE /incidents/{incident_id}` | Удалить запись |
