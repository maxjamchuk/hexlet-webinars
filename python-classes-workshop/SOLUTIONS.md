Материал для преподавателя. Условия находятся в [PRACTICE.md](PRACTICE.md). Каждый фрагмент соответствует эталонной стадии и работает с её локальными фикстурами.

## 1. Представления `Playlist`

```python
def __str__(self):
    return f"{self.name} — треков: {len(self._tracks)}"

def __repr__(self):
    return f"Playlist(name={self.name!r}, tracks={self._tracks!r})"
```

Человеку достаточно имени и размера, разработчику полезны поля и треки. На этом этапе `len(self)` ещё недоступен. Частые ошибки: вызвать `len(self)` заранее, применить `str()` к внутреннему списку вручную, забыть `!r` и сломать вывод строк с кавычками. При разборе покажите, что `repr(list)` использует `repr()` элементов. [Эталон 01](01-representation/models.py).

## 2. Равенство `Track`

```python
def __eq__(self, other):
    if not isinstance(other, Track):
        return NotImplemented
    return (self.artist, self.title, self.year) == (
        other.artist, other.title, other.year
    )
```

Сравнение кортежей проверяет все три поля в порядке их перечисления. `NotImplemented` позволяет Python попробовать обратное сравнение; это не исключение `NotImplementedError`. Частые ошибки: `return False` для чужого типа, сравнение через `is`, проверка только названия, ручное добавление `__hash__` без осмысленного контракта. Подчеркните разницу между идентичностью и равенством и прямую проверку `first.__eq__("A Forest") is NotImplemented`. [Эталон 02](02-equality/models.py).

## 3. Длина и истинность

Ответ: `6 0 True False`. `Playlist.__len__` возвращает длину внутреннего списка; при отсутствии `__bool__` Python использует эту длину для истинности. Подчеркните, что длина должна быть неотрицательным целым числом. [Эталон 03](03-length/models.py).

## 4. Принадлежность

Ответ: `True True False` и `False True`. Исходный объект есть в списке; независимая копия тоже находится благодаря `Track.__eq__`. Другой трек и строка отсутствуют. Частые ошибки: считать, что `in` сравнивает идентичность, или молча совмещать поиск `Track` с поиском подстроки по названию. Подчеркните один понятный контракт: `__contains__` делегирует `track in self._tracks`. [Эталон 04](04-membership/models.py).

## 5. Индексы и срезы

```python
def __getitem__(self, index):
    return self._tracks[index]
```

Список уже обрабатывает отрицательные индексы, срезы и `IndexError`. Срез возвращает обычный `list[Track]`. Частые ошибки: обработать только целые индексы, превращать срез в `Playlist`, перехватывать `IndexError` и возвращать `None`. При разборе запустите цикл `for` до добавления `__iter__`: Python может последовательно запрашивать индексы, пока не получит `IndexError`. [Эталон 05](05-indexing/models.py).

## 6. Итератор

```python
def __iter__(self):
    return iter(self._tracks)
```

`iter(list)` возвращает итератор, который хранит позицию и поддерживает `next()`. Каждый новый вызов `iter(playlist)` создаёт независимый обход. Частые ошибки: вернуть сам список, вернуть `self` без собственного `__next__`, хранить один общий исчерпываемый итератор в плейлисте. Подчеркните разницу между итерируемым объектом и итератором; ручной счётчик здесь ничего не добавляет. [Эталон 06](06-iteration/models.py).
