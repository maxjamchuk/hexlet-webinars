## Как вести live coding и восстанавливаться после ошибки

Эталонные стадии полностью рабочие. Для живого написания нового метода скопируйте **предыдущую** стадию в отдельную папку `scratch-XX`, отредактируйте её `models.py`, затем сравните с новой эталонной стадией. Папки `scratch-*` скрыты от Git через `.gitignore`. Например, перед блоком 01:

```shell
python -c "import shutil; shutil.copytree('00-start', 'scratch-01')"
```

Для следующего блока меняйте оба номера: `01-representation` → `scratch-02`, затем `02-equality` → `scratch-03` и так далее. Запускайте `python scratch-01/demo.py` для прежнего поведения. Чтобы проверить новую операцию, можно скопировать демонстрацию **новой** стадии в рабочую папку:

```shell
python -c "import shutil; shutil.copyfile('01-representation/demo.py', 'scratch-01/demo.py')"
python scratch-01/demo.py
```

Пока метод не дописан, новая демонстрация может завершиться ошибкой — это ожидаемо только в рабочей копии. Если эксперимент зашёл в тупик, создайте новую копию с другим суффиксом, например `scratch-01b`; эталонные файлы не затронуты. После live coding всегда запускайте готовое демо соответствующей стадии. Для практики на предсказание кода менять не нужно.

## 00:00–00:08 — исходные классы и идея протокола

- **Открыть:** `00-start/models.py`, `fixtures.py`, `demo.py`; затем `00-start/README.md`.
- **До запуска:** напомнить только, что у экземпляра есть атрибуты. `Playlist` хранит отдельную копию входного списка. Протокол — ожидаемое поведение, которое Python обнаруживает по специальным методам; наследоваться от `list` для этого не требуется. Обычный список уже умеет `len()` и `for`, наши классы пока нет.
- **Команда:** `python 00-start/demo.py`.
- **Вывод:** адрес в стандартном представлении может меняться; оба ожидаемых `TypeError` перехвачены. Покажите, что `Track` и `Playlist` всё же созданы и хранят данные.
- **Вопрос:** «Почему `len([1, 2])` работает, а `len(playlist)` — нет?» **Ответ:** список предоставляет протокол длины, а у `Playlist` пока нет `__len__`.
- **Практика:** нет. Решение этого блока — готовая [стадия 00](00-start/models.py).
- **Переход:** предложить улучшить вывод объектов; копировать `00-start` в `scratch-01` по инструкции выше.
- **Если отстаём:** сократить обсуждение начального `repr()` до одного примера, сохранить оба перехваченных исключения.

## 00:08–00:22 — `__str__` и `__repr__`

- **Открыть:** `01-representation/models.py`, `demo.py`, `test_models.py`; для live coding — `scratch-01/models.py`.
- **До запуска:** `str()` и `print()` ориентированы на читаемую строку. `repr()` нужен для информативного представления; восстанавливаемое выражение полезно, когда практично, но не является универсальной гарантией. В списке объекты показываются через `repr()`.
- **Live coding:** сначала предложить `Track.__str__`, затем `Track.__repr__` с `!r`. В рабочей копии добавить оба метода и сравнить `print(track)` с `print([track])`. Затем практика №1 по методам `Playlist`; в `__str__` пока `len(self._tracks)`.
- **Команда:** `python 01-representation/demo.py` после сравнения с рабочей копией.
- **Вывод:** `The Cure — A Forest (1980)`, `Track(artist='The Cure', title='A Forest', year=1980)`, и внутри списка второй формат. Плейлист выводит имя и число 6, `repr()` включает треки.
- **Вопрос:** «Почему `print([track])` не равен `print(track)`?» **Ответ:** контейнер показывает `repr()` элемента, а прямой `print(track)` использует `str()`.
- **Практика №1:** 00:16–00:19, 3 минуты; условие в [PRACTICE.md](PRACTICE.md#1-представления-плейлиста--написание-кода), решение в [SOLUTIONS.md](SOLUTIONS.md#1-представления-playlist). Дайте подсказку про `{self._tracks!r}`, затем запустите эталон.
- **Переход:** спросить, равны ли два отдельно созданных объекта с одинаковыми полями; открыть `02-equality`.
- **Если отстаём:** показать `Track.__repr__` готовым, оставить написание `Playlist` как практику.

## 00:22–00:35 — `__eq__`, `==`, `is`

- **Открыть:** `02-equality/models.py`, `demo.py`, `test_models.py`; для live coding скопировать `01-representation` в `scratch-02`.
- **До запуска:** `is` проверяет идентичность, `==` — равенство. `Track` сравнивает `artist`, `title`, `year`. Чужой тип получает `NotImplemented`, а `NotImplementedError` — другое, исключение.
- **Live coding:** попросить предложить кортеж полей, добавить `__eq__` с `isinstance`. Прямо вызвать метод с чужим типом, не использовать `bool(NotImplemented)`.
- **Команда:** `python 02-equality/demo.py`.
- **Вывод:** `first is second: False`, `first == second: True`, сравнение с другой композицией и строкой даёт `False`. Прямой вызов возвращает `NotImplemented`; `hash(first)` вызывает перехваченный `TypeError`, поскольку при своём `__eq__` без `__hash__` объект становится нехешируемым.
- **Вопрос:** «Можно ли возвращать `False` для чужого типа?» **Ответ:** лучше `NotImplemented`, чтобы Python мог попробовать сравнение другой стороны. «Нужно ли вручную писать `__ne__`?» **Ответ:** здесь нет.
- **Практика №2:** 00:29–00:32, 3 минуты; [условие](PRACTICE.md#2-равенство-композиций--написание-кода), [решение](SOLUTIONS.md#2-равенство-track). Проверить `first.__eq__("A Forest") is NotImplemented`.
- **Переход:** переключить внимание с одной композиции на коллекцию: у плейлиста естественна длина.
- **Если отстаём:** сократить разговор о хешировании до одного перехваченного `TypeError`.

## 00:35–00:47 — `__len__` и `bool()`

- **Открыть:** `03-length/models.py`, `demo.py`, `test_models.py`; для live coding скопировать `02-equality` в `scratch-03`.
- **До запуска:** размер — свойство коллекции, но не отдельной композиции. `__len__` должен возвращать неотрицательное целое число. В этой модели `__bool__` не определяем: при проверке истинности Python использует длину.
- **Live coding:** добавить `Playlist.__len__` делегированием списку и поменять `Playlist.__str__` с `len(self._tracks)` на `len(self)`. Объяснять `len(obj)` как применение протокола, не как точный обычный вызов `obj.__len__()`.
- **Команда:** `python 03-length/demo.py`.
- **Вывод:** `6`, `0`, `True`, `False`; обе ветки `if` соответствуют наполненности. Локальный ошибочный `__len__`, возвращающий `-1`, вызывает перехваченный `ValueError`.
- **Вопрос:** «Почему `bool(empty)` — `False`, хотя экземпляр существует?» **Ответ:** длина равна нулю. «Нужен ли `Track.__len__`?» **Ответ:** нет естественного смысла.
- **Практика №3:** 00:42–00:44, 2 минуты; [условие](PRACTICE.md#3-длина-и-истинность--предсказание-поведения), [ответ](SOLUTIONS.md#3-длина-и-истинность). Сначала ответ в чате, потом вывод.
- **Переход:** размер появился; теперь спросить, содержит ли коллекция равный трек.
- **Если отстаём:** не разбирать локальный отрицательный пример подробно, оставить факт ограничения длины.

## 00:59–01:11 — `__getitem__`, срезы и резервная итерация

- **Открыть:** `05-indexing/models.py`, `demo.py`, `test_models.py`; для live coding скопировать `04-membership` в `scratch-05`.
- **До запуска:** списку уже известны положительные и отрицательные индексы, срезы и `IndexError`. Мы делегируем их без дополнительного класса. Один индекс возвращает `Track`; срез — обычный `list[Track]`.
- **Live coding:** добавить `__getitem__`, выполнить проверки из практики; намеренно не добавлять `__iter__`.
- **Команда:** `python 05-indexing/demo.py`.
- **Вывод:** первый и последний треки, срез из двух элементов и `type(...): list`; неверный индекс даёт перехваченный `IndexError`. Затем **сюрприз:** `for` перечисляет все шесть треков, хотя `__iter__` отсутствует в `Playlist.__dict__`.
- **Вопрос:** «Как сработал `for` без `__iter__`?» **Ответ:** резервный протокол последовательности запрашивает индексы `0`, `1`, `2`, ... до `IndexError`.

## 01:11–01:22 — `__iter__` и `next()`

- **Открыть:** `06-iteration/models.py`, `demo.py`, `test_models.py`; для live coding скопировать `05-indexing` в `scratch-06`.
- **До запуска:** итерируемый плейлист может выдавать новые итераторы; сам итератор помнит позицию и отвечает на `next()`. `__iter__` обязан вернуть итератор, не просто список. `StopIteration` означает завершение обхода.
- **Live coding:** добавить `return iter(self._tracks)`. Пусть студенты сначала найдут ошибку в варианте `return self._tracks`; не менять эталонный `Playlist` для демонстрации ошибки.
- **Команда:** `python 06-iteration/demo.py`.
- **Вывод:** `iter(playlist) is playlist: False`, `iter(iterator) is iterator: True`, два вызова `next()` дают первые два трека. Цикл проходит все шесть; после исчерпания итератора перехвачен `StopIteration`. Локальный неправильный класс даёт перехваченный `TypeError`.
- **Вопрос:** «Почему нельзя вернуть список?» **Ответ:** он итерируемый, но сам не является итератором для `next()`; нужен `iter(list)`. «Повторный цикл начнётся сначала?» **Ответ:** да, новый `iter(playlist)` создаёт новый итератор.
- **Практика №6:** 01:17–01:20, 3 минуты; [условие](PRACTICE.md#6-исправление-итератора--написание-кода), [решение](SOLUTIONS.md#6-итератор).
- **Переход:** открыть финальную стадию и показать весь публичный интерфейс подряд.
- **Если отстаём:** один `next()` вместо двух и короткое объяснение `StopIteration`; пример неверного возврата списка оставить.
