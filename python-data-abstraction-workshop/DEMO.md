# Сценарий демонстрации

Команды выполняются из каталога `python-data-abstraction-workshop/`. Все `demo.py` работают без ввода. Перед занятием запустите `python tools/smoke_check.py`. В каждом блоке сначала спросите студентов о результате, затем запускайте команду.

## Основной маршрут — 90 минут

### 00:00–00:20 — Рабочий лабиринт

- **Открыть:** `00-naive/fixtures.py`, затем `game.py`: `get_tile()` (строка 8), `move()` (12), `render()` (32), и `demo.py`: `main()` (5).
- **Команда:** `python 00-naive/demo.py`.
- **Вывод:** `START: (1, 1)`, карта с `@`, `MOVE a: blocked`, затем успешные `MOVE`, `EXIT REACHED`, `WIN`, карта с `@` на выходе.
- **Объяснение:** `world[y][x]` читает символ клетки; игрок хранится в состоянии игры, поэтому исходная карта не меняется. Показать интерактивный режим: `python 00-naive/play.py`, ввести `z`, `d`, `q`.
- **Вопрос:** Почему попытка `a` не сдвигает игрока? **Ответ:** слева стена `#`; проверка находится в `move()`. Частая ошибка — думать, что `@` уже записан в строку карты.
- **Переход:** что будет, если клетку больше нельзя читать через `world[y][x]`?

### 00:20–00:35 — Намеренная поломка

- **Открыть:** `01-broken-representation/fixtures.py` и `game.py`: `get_tile()` (8); сравнить с файлом стадии 00.
- **Команда:** `python 01-broken-representation/demo.py`.
- **Вывод:** три поясняющие строки `Stage 01: representation changed`, `The game still expects world[y][x].`, `An error is expected.`, затем traceback с `KeyError: 0`; код завершения ненулевой.
- **Объяснение:** словарь содержит все клетки под ключами `(x, y)`, а старый код пытается получить ключ `0`. Это запланированный результат. Тесты `python -m unittest discover -s 01-broken-representation -p "test_*.py" -v` завершаются успешно.
- **Вопрос:** Где возникла ошибка: в маршруте игры или в чтении клетки? **Ответ:** в чтении клетки. Частая ошибка — пытаться менять команды маршрута вместо устранения зависимости от формата карты.
- **Переход:** поместим знание о формате в один файл.

### 00:35–00:52 — Интерфейс карты

- **Открыть:** `02-interface-list/world.py`: `make_world()` (1), `get_tile()` (17), `is_walkable()`; `game.py`: `move()` (11), `render()` (29).
- **Команда:** `python 02-interface-list/demo.py`.
- **Вывод:** те же `START`, блокировка, ходы, `EXIT REACHED`, `WIN`.
- **Объяснение:** вместо `world[y][x]` игра вызывает `get_tile(world, x, y)`. `make_world` — конструктор; `get_tile`, `get_width`, `get_height` — селекторы. Все публичные функции `world.py` составляют интерфейс и скрывают хранение.
- **Вопрос:** Почему дополнительные функции пока не сократили код? **Ответ:** они создают границу; выигрыш станет виден при следующей замене. Частая ошибка — считать интерфейс полезным только если строк кода стало меньше.
- **Переход:** теперь заменим список словарём, сохранив интерфейс.

### 00:52–01:07 — Кульминационная демонстрация: список → словарь

- **Открыть рядом:** `02-interface-list/world.py`: `make_world()` (1), `get_tile()` (17); `03-interface-dict/world.py`: `make_world()` (1), `get_tile()` (22). Затем сравнить `game.py` обеих стадий.
- **Команда:** `python 03-interface-dict/demo.py`; для автоматической проверки равенства и результата — `python tools/smoke_check.py`.
- **Вывод:** те же карта, ходы, `EXIT REACHED`, `WIN`; smoke-check сообщает `PASS identical game.py: 02-interface-list, 03-interface-dict, 04-invariants` и `PASS equivalent game outputs: 02-04 and 05-06`.
- **Объяснение:** `world.py` теперь содержит `width`, `height` и словарь `cells[(x, y)]`. Интерфейс остался прежним, поэтому в `game.py` не изменился ни один байт. Это главная демонстрация занятия.
- **Вопрос:** Почему `game.py` не проверяет `isinstance(world, dict)`? **Ответ:** выбор представления принадлежит `world.py`; проверка в игре снова связала бы её с хранением. Частая ошибка — переносить ветвление по типу в игровой код.
- **Переход:** конструктор может также гарантировать, что карта вообще пригодна для игры.

### 01:07–01:19 — Инварианты

- **Открыть:** `04-invariants/world.py`: `make_world()` (1), порядок `ValueError`; `demo.py`: `main()` (6).
- **Команда:** `python 04-invariants/demo.py`.
- **Вывод:** обычная победа, затем пять строк `EXPECTED INVALID MAP:` для пустоты, разной длины, символа `X`, отсутствия и удвоения выхода. Скрипт завершится с кодом 0.
- **Объяснение:** проверки идут в порядке «непустота → ненулевая одинаковая ширина → допустимые символы → один выход». Это инварианты структуры. Запрет двигаться в стену — правило игры. Изменяемый словарь можно испортить после создания прямой записью, поэтому обращаться к нему следует через согласованный интерфейс.
- **Вопрос:** Что увидим для карты `("EX", "#")`? **Ответ:** ошибка ширины, потому что эта проверка идёт раньше проверки символов. Частая ошибка — ожидать `unsupported tile: X`.
- **Переход:** теперь меняются сами правила игры.

### 01:19–01:26 — Ключ от выхода

- **Открыть:** `05-key-mechanic/world.py`: `make_world()` (1); `game.py`: `move()` (11), `render()` (36); `demo.py`: маршруты в `main()` (16).
- **Команда:** `python 05-key-mechanic/demo.py`.
- **Вывод:** маршрут A заканчивается `EXIT REACHED`, `EXIT LOCKED: key required`; маршрут B содержит `KEY COLLECTED`, `EXIT REACHED`, `WIN`.
- **Объяснение:** `has_key` хранится в состоянии игры. Исходная карта остаётся с `K`, а отображение после подбора показывает `.`. Новое бизнес-правило требует изменения `game.py`; чтение карты по-прежнему идёт через интерфейс.
- **Вопрос:** Почему маршрут A может уйти с выхода? **Ответ:** без ключа состояние `won` остаётся `False`; `E` проходим. Частая ошибка — считать вход на `E` безусловной победой.
- **Переход:** подвести итог: смена хранения не меняла игровую логику, смена правил — меняла.

### 01:26–01:30 — Итог

Попросите студентов назвать конструктор, два селектора и файл, который менялся при переходе 02 → 03. Ответ: `make_world()`, например `get_tile()` и `get_width()`, менялся `world.py`. Покажите [PRACTICE.md](PRACTICE.md) и [SOLUTIONS.md](SOLUTIONS.md) для самостоятельной работы.

## Расширенный маршрут — 110–120 минут

Проведите основной маршрут без сокращения демонстрации 02 → 03. После него добавьте 12 минут на резерв и 8–18 минут на практику:

### 01:30–01:42 — Разреженная карта

- **Открыть:** `06-bonus-sparse-world/world.py`: `make_world()` (1), `get_tile()` (39); сравнить со стадией 05. `game.py` обеих стадий совпадает побайтово.
- **Команда:** `python 06-bonus-sparse-world/demo.py` и `python tools/smoke_check.py`.
- **Вывод:** оба маршрута совпадают со стадией 05; smoke-check подтверждает равенство `game.py`.
- **Объяснение:** `cells` хранит стены, выход и ключ. `get_tile()` проверяет границы до `.get((x, y), ".")`; иначе за пределами карты возникнут свободные клетки.
- **Вопрос:** Что вернёт наивное `.get((-1, 1), ".")`? **Ответ:** `.`. Частая ошибка — считать отсутствующий ключ словаря границей карты.
- **Переход:** решить упражнения 4–7 из практики.
