# 07 — Покрытие

## Цель

Найти код, который зелёный набор тестов ещё не выполнял.

## Что изменилось

В `inspect_cargo()` добавлен карантин для `hazardous`, а проверка этого правила вынесена в новый тестовый файл.

## Файлы для показа

- `customs.py` — новая ветка с `return "quarantine"`;
- `tests/test_calculate_fee.py` и `tests/test_inspect_cargo.py` — старые тесты;
- `tests/test_hazardous_cargo.py` — тест, закрывающий пропуск.

## Подготовка

Все команды выполняются из каталога `07-coverage`.

```bash
uv sync --locked
```

## Запуск

Сначала запускаются только старые тесты:

```bash
uv run pytest tests/test_calculate_fee.py tests/test_inspect_cargo.py --cov=customs --cov-report=term-missing
```

Затем весь набор:

```bash
uv run pytest --cov=customs --cov-report=term-missing
```

## Ожидаемый результат

Первый процесс завершается успешно: `11 passed`, фактическое покрытие — 95%, а `Missing` указывает на строку 35 с возвратом `quarantine`. Полный запуск даёт `12 passed`, 100% statement coverage и код `0`.

## Что важно объяснить

Зелёные тесты не гарантируют выполнения всего кода. `Missing` помогает найти пропущенные строки, но даже 100% покрытия не доказывает отсутствие ошибок. Branch coverage здесь не рассматривается.

## Ограничение текущего решения

Покрытие нашло пропуск для существующего правила, но новое требование ещё не проведено через цикл разработки; следующая стадия начинает TDD с красного теста.
