# Python: Автоматическое тестирование

> От ручных проверок через print() до pytest, покрытия и TDD

## О воркшопе

Воркшоп проводит начинающего разработчика через последовательные версии pure-Python-проекта «Космическая таможня». Каждая стадия — самостоятельный проект: её можно открыть, подготовить и запустить независимо от соседних.

Материал рассчитан на студентов 2 модуля, которые знают базовый синтаксис Python, функции, коллекции, модули, командную строку и Git. Продолжительность основного маршрута — 90–120 минут.

После воркшопа студент сможет написать первый тест на `pytest`, подобрать позитивные, негативные и граничные сценарии, применить параметризацию и простую фикстуру, прочитать отчёт о покрытии и пройти цикл Red → Green → Refactor.

## Требования

- Git;
- Python 3.12+;
- [uv](https://docs.astral.sh/uv/).

Production-код использует только стандартную библиотеку. Тестовые зависимости каждой стадии зафиксированы в её собственном `uv.lock`.

## Бизнес-правила

`calculate_fee(weight, cargo_type)` использует тарифы 100 для `standard`, 150 для `fragile` и 300 для `hazardous`. Масса должна быть больше нуля, тип груза должен быть известен, а при массе строго больше 20 кг добавляется 500. На границе 20 кг доплаты нет.

`inspect_cargo(manifest)` сначала отклоняет незадекларированный груз, затем груз тяжелее 50 кг, после этого отправляет `hazardous` и `alien_sample` в карантин. Остальные манифесты принимаются.

## Карта стадий

| Каталог              | Тема                       | Нормальный результат                       |
| -------------------- | -------------------------- | ------------------------------------------ |
| `00-manual-checks`   | Проверки глазами           | Команда успешна, но один результат неверен |
| `01-first-test`      | Первый тест                | 1 passed                                   |
| `02-failing-test`    | Чтение падения             | 1 failed, 1 passed                         |
| `03-test-scenarios`  | Сценарии и `pytest.raises` | 6 passed                                   |
| `04-parametrize`     | Параметризация             | 8 passed                                   |
| `05-fixtures`        | Фикстуры                   | 11 passed                                  |
| `06-test-quality`    | Качество тестов            | 11 passed                                  |
| `07-coverage`        | Покрытие                   | 12 passed, 100% при полном запуске         |
| `08-tdd-red`         | TDD: Red                   | 1 failed, 12 passed                        |
| `09-tdd-green`       | TDD: Green                 | 13 passed                                  |
| `10-tdd-refactor`    | TDD: Refactor              | 13 passed                                  |
| `11-doctest-reserve` | `doctest`, резерв          | 2 doctest + 13 pytest                      |

Стадии `02-failing-test` и `08-tdd-red` красные намеренно: код завершения `pytest` равен `1`. Это учебный результат, а не поломка проекта.

Основной маршрут проходит стадии `00`–`10`. Стадия `11-doctest-reserve` — резерв, если после основного материала осталось время.

## Быстрый старт

Перейдите в нужную стадию; например:

```bash
cd python-automatic-testing/01-first-test
uv sync --locked
uv run pytest -v
```

Точные команды и ожидаемый результат находятся в локальном `README.md` каждой стадии.

## Покрытие

В `07-coverage` сначала запустите старые тесты, чтобы увидеть непокрытую строку:

```bash
uv run pytest tests/test_calculate_fee.py tests/test_inspect_cargo.py --cov=customs --cov-report=term-missing
```

Затем запустите весь набор:

```bash
uv run pytest --cov=customs --cov-report=term-missing
```

Итоговую стадию можно проверить той же командой из `10-tdd-refactor`.

## Smoke-check

Из каталога `python-automatic-testing` выполните:

```bash
python tools/smoke_check.py
```

Скрипт синхронизирует окружение каждой стадии, запускает её основную команду и учитывает ожидаемые падения `02` и `08`.

## Возможные проблемы

### `uv` не найден

Проверьте установку:

```bash
uv --version
```

### Неподходящая версия Python

Проекту нужен Python 3.12 или новее:

```bash
python --version
uv run python --version
```

### Команда запущена не из каталога стадии

У каждой стадии собственные `pyproject.toml` и `uv.lock`. Перед `uv sync --locked` и демонстрационной командой перейдите в нужный каталог.

### В `02` или `08` тесты красные

Это ожидаемое состояние учебных стадий: в них `pytest` должен завершиться с кодом `1`.

### Coverage показывает другой номер строки

Номер может измениться после форматирования. Важен смысл: в неполном запуске не выполнена строка `return "quarantine"`.

### Создались служебные файлы

Каталоги `.venv`, `__pycache__`, `.pytest_cache` и файлы `.coverage` игнорируются общим `.gitignore` этого воркшопа.

## Что остаётся за рамками

Воркшоп не рассматривает ООП, HTTP, базы данных, веб-фреймворки, асинхронность, моки, тестирование файловой системы, сложные фикстуры, property-based testing и branch coverage.
