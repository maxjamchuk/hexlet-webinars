# 06 — Качество тестов

## Цель

Сделать тесты читаемыми, содержательными и независимыми.

## Что изменилось

Хорошие тесты разделены по функциям. В `examples/` добавлены читаемые антипримеры, а ввод и вывод в `main.py` отделены от расчёта.

## Файлы для показа

- `tests/test_calculate_fee.py` и `tests/test_inspect_cargo.py` — основной набор;
- `examples/bad_tests.py` — плохие имена, отсутствие `assert`, несвязанные правила и общий изменяемый словарь;
- `examples/hard_to_test.py` и `main.py` — смешанная и разделённая логика.

## Подготовка

Все команды выполняются из каталога `06-test-quality`.

```bash
uv sync --locked
```

## Запуск

```bash
uv run pytest -v
```

## Ожидаемый результат

Обычный запуск собирает только каталог `tests/`: `11 passed`, код процесса `0`.

## Что важно объяснить

Имя теста описывает поведение, содержательная проверка обязательна, а один тест проверяет одну связанную идею. Общий изменяемый словарь создаёт зависимость от порядка. Отделение бизнес-логики от `input()` и `print()` упрощает тестирование без патчей CLI.

## Ограничение текущего решения

Все тесты проходят, но неизвестно, выполнялись ли все строки; следующая стадия измеряет покрытие.
