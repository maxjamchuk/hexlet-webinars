# Основы командной строки

Материалы к воркшопу для студентов первого модуля Hexlet.

За время встречи вы научитесь ориентироваться в файловой системе из терминала, создавать, копировать, перемещать и удалять файлы и директории, перенаправлять вывод в файл, получать справку о командах и понимать, как shell находит установленные программы.

Воркшоп рассчитан примерно на 90–120 минут. Основной формат каждого раздела: короткое объяснение, демонстрация преподавателя в настоящем терминале и небольшое задание. Если терминал не работает, команду для задания можно написать в чат.

## Перед началом

Команды в материале рассчитаны на sh-совместимую командную строку в одной из сред:

- Linux;
- WSL;
- Git Bash;

Приглашение командной строки может выглядеть по-разному. В примерах ниже показаны только команды: символ `$` перед ними вводить не нужно.

Команды работают с реальными файлами. Для экспериментов лучше создать отдельную учебную директорию и внимательно проверять путь перед удалением.

## Основные понятия

### Терминал и shell

**Терминал** — это приложение с текстовым окном, в котором мы вводим команды и видим их вывод.

**Shell** — программа внутри терминала, которая читает введённую строку, разбирает её и запускает нужную команду. Bash и Zsh — примеры shell. Git Bash и WSL тоже дают среду, где можно работать с командами из этого воркшопа.

Терминал и shell — не одно и то же: терминал отвечает за окно и взаимодействие с пользователем, а shell — за понимание и выполнение команд.

### Команда, опция и аргумент

Общую форму вызова можно записать так:

```text
command [options] [arguments]
```

Квадратные скобки здесь показывают необязательные части. В настоящую команду их добавлять не нужно.

- **Команда** говорит, какое действие выполнить. Это может быть отдельная программа или команда, которую обрабатывает сам shell.
- **Опция** меняет поведение команды. Обычно она начинается с `-` или `--`.
- **Аргумент** указывает, с чем работать: например, путь к файлу или директории.

Примеры:

```bash
ls -l projects
cp file.txt backup.txt
mkdir new_project
```

В первой строке `ls` — команда, `-l` — опция подробного вывода, а `projects` — аргумент. Во второй строке команда `cp` получает два аргумента: что копировать и куда. В третьей строке `new_project` — имя создаваемой директории.

Командная строка — не набор магических сочетаний, которые нужно запомнить целиком. Мы запускаем команду или программу и передаём ей опции и аргументы.

### Файлы, директории и текущая директория

**Файл** хранит данные: текст, изображение, настройки или программу.

**Директория** хранит файлы и другие директории. Её также часто называют каталогом или папкой.

**Текущая рабочая директория** — директория, относительно которой shell выполняет команды. Если указать путь `notes.txt`, shell будет искать этот файл в текущей директории.

## Где мы находимся: `pwd` и `ls`

Команда `pwd` показывает полный путь к текущей рабочей директории:

```bash
pwd
```

Команда `ls` показывает содержимое текущей директории:

```bash
ls
```

Можно передать ей другую директорию:

```bash
ls projects
```

Опция `-l` включает подробный вывод: права, владельца, размер и время изменения:

```bash
ls -l
```

Опция `-a` показывает в том числе скрытые имена. В sh-совместимых средах они обычно начинаются с точки:

```bash
ls -a
```

Команда `clear` очищает видимую область терминала, но не удаляет файлы и не отменяет выполненные команды:

```bash
clear
```

1. Узнайте, в какой директории вы сейчас находитесь.
2. Покажите обычное содержимое текущей директории.
3. Покажите скрытые файлы.
4. Напишите в чат команду для подробного просмотра содержимого, если не можете выполнить её в терминале.

## Пути и переход между директориями

Путь показывает, где находится файл или директория.

### Абсолютный путь

**Абсолютный путь** задаёт расположение от корня файловой системы и начинается с `/`:

```text
/home/user/projects
```

Такой путь не зависит от текущей директории. На macOS домашний каталог часто находится по пути вида `/Users/user`, а Git Bash может показывать диски Windows путями вида `/c/Users/user`. Принцип остаётся тем же: начальный `/` означает путь от корня среды.

### Относительный путь

**Относительный путь** задаётся от текущей рабочей директории:

```text
projects
projects/hello.txt
../backup
```

Один и тот же относительный путь может указывать на разные места в зависимости от того, где мы сейчас находимся.

В путях часто встречаются специальные обозначения:

- `.` — текущая директория;
- `..` — родительская директория, то есть на один уровень выше;
- `~` — домашняя директория текущего пользователя.

Shell раскрывает `~` в путь к домашней директории. Поэтому `~/projects` приводит к одному и тому же месту независимо от текущей директории.

### Команда `cd`

`cd` меняет текущую рабочую директорию:

```bash
cd projects
```

Перейти на один уровень выше:

```bash
cd ..
```

Остаться в текущей директории:

```bash
cd .
```

Перейти в домашнюю директорию:

```bash
cd ~
```

Перейти по абсолютному пути:

```bash
cd /home/user/projects
```

Последний путь — учебный пример. На своём компьютере нужно подставить существующий путь, который можно узнать с помощью `pwd`.

### Мини-практика

1. Определите тип каждого пути: `/home/user/projects`, `projects/hello.txt`, `../backup`.
2. Перейдите в домашнюю директорию.
3. Перейдите в любую существующую директорию, затем вернитесь на уровень выше.
4. Проверьте новое положение с помощью `pwd`.

## Создание директорий и файлов

`mkdir` создаёт директорию:

```bash
mkdir workshop
```

`touch` удобно использовать, чтобы создать пустой файл:

```bash
touch hello.txt
```

Если файл уже существует, `touch` не очищает его, а обновляет время изменения.

`echo` выводит переданный текст:

```bash
echo "Hello"
```

`cat` выводит содержимое небольшого текстового файла:

```bash
cat hello.txt
```

Для очень больших файлов `cat` неудобен, но для коротких учебных примеров подходит хорошо.

### Мини-практика

1. Создайте директорию `workshop`.
2. Перейдите в неё.
3. Создайте пустой файл `hello.txt`.
4. Проверьте результат с помощью `ls -l`.
5. Выведите содержимое файла. Какой результат ожидается от пустого файла?

## Копирование, перемещение и удаление

### `cp` — копирование

`cp` получает путь к источнику и путь к копии:

```bash
cp hello.txt hello-copy.txt
```

Скопировать файл в директорию `backup`:

```bash
cp hello.txt backup/hello.txt
```

Исходный файл после копирования остаётся на месте.

### `mv` — перемещение и переименование

Переместить файл в другую директорию:

```bash
mv hello.txt backup/hello.txt
```

Переименование — это перемещение под новым именем в той же директории:

```bash
mv hello.txt greeting.txt
```

### `rm` и `rmdir` — удаление

`rm` удаляет файл:

```bash
rm greeting.txt
```

Будьте внимательны: обычно файл удаляется без перемещения в корзину. Перед выполнением команды проверьте имя и текущую директорию с помощью `pwd` и `ls`.

`rmdir` удаляет только пустую директорию:

```bash
rmdir backup
```

Если внутри что-то осталось, команда откажется удалять директорию. Для первого знакомства это полезное безопасное ограничение.

### Мини-практика

Выполняйте шаги внутри учебной директории `workshop`:

1. Создайте директорию `backup`.
2. Скопируйте `hello.txt` в `backup`, сохранив то же имя.
3. Переименуйте исходный `hello.txt` в `greeting.txt`.
4. Проверьте содержимое обеих директорий.
5. Удалите копию из `backup`, а затем удалите ставшую пустой директорию.

Если терминал недоступен, напишите по одной команде для шагов 1–3 в чат.

## Перенаправление вывода

Обычно `echo` пишет результат в терминал. Оператор `>` направляет этот вывод в файл:

```bash
echo "Hello" > hello.txt
```

`>` создаёт файл, если его нет, и записывает в него вывод команды. Если файл уже существовал, его прежнее содержимое будет заменено.

Оператор `>>` дописывает вывод в конец файла:

```bash
echo "World" >> hello.txt
```

Посмотрим результат:

```bash
cat hello.txt
```

В файле будут две строки:

```text
Hello
World
```

### Мини-практика

1. Запишите своё имя в файл `name.txt` с помощью `echo` и `>`.
2. Допишите в тот же файл название города с помощью `>>`.
3. Покажите содержимое файла командой `cat`.
4. Ответьте: какой оператор заменит старое содержимое файла, а какой сохранит его и допишет новое?

## Как получить справку и найти программу

Многие команды поддерживают опцию `--help`:

```bash
ls --help
```

Общая форма:

```text
command --help
```

Она показывает назначение команды и доступные опции. Набор опций может отличаться между системами. В частности, некоторые системные команды macOS не поддерживают `--help`.

Команда `man` открывает страницу документации:

```bash
man ls
```

Чтобы выйти из просмотрщика `man`, обычно достаточно нажать `q`. `man` доступен во многих Linux- и macOS-средах, но может отсутствовать в Git Bash или в минимальной установке WSL.

Команда `command -v` сообщает, откуда shell возьмёт указанную команду:

```bash
command -v git
command -v python
```

Если `python` не найден, в некоторых системах программа может называться `python3`:

```bash
command -v python3
```

Пустой вывод обычно означает, что shell не нашёл команду под таким именем.

### Мини-практика

1. Найдите расположение программы `git` с помощью `command -v`.
2. Попробуйте получить краткую справку для `ls`.
3. Если доступен `man`, откройте документацию `pwd` и выйдите из неё.

## Переменные окружения и `PATH`

Переменная окружения — именованное значение, которое shell и запускаемые программы получают из окружения. В переменных могут храниться пути, настройки языка, режим работы программы и другие параметры.

`HOME` содержит путь к домашней директории пользователя:

```bash
echo $HOME
```

`PATH` содержит список директорий, в которых shell ищет исполняемые программы:

```bash
echo $PATH
```

Когда мы вводим `git`, shell просматривает директории из `PATH` и пытается найти там подходящую программу. Результат поиска можно увидеть так:

```bash
command -v git
command -v python
```

Команда `export` создаёт переменную окружения для текущего сеанса shell и программ, которые будут из него запущены:

```bash
export MY_NAME=Max
echo $MY_NAME
```

Вокруг `=` в таком присваивании пробелы не ставятся. После закрытия терминала значение, заданное этим способом, обычно исчезнет. Для этого воркшопа достаточно понимать временную переменную; постоянную настройку разных shell не разбираем.

### Мини-практика

1. Выведите значения `HOME` и `PATH`.
2. Создайте переменную `MY_NAME` со своим именем.
3. Выведите её значение.
4. Объясните своими словами связь между `PATH` и `command -v`.

## Установка программ

Способ установки зависит от операционной системы и выбранной среды. Например, команды могут выглядеть так:

```bash
# Ubuntu / Debian
sudo apt install ...

# Fedora
sudo dnf install ...

# macOS с установленным Homebrew
brew install ...
```

Многоточие — место для имени конкретной программы, а не часть готовой команды. В Git Bash обычно используют установщики Windows или менеджер пакетов Windows, а программы внутри WSL устанавливают отдельно от Windows.

Не нужно запоминать команды всех пакетных менеджеров. Надёжный порядок такой:

1. Открыть официальную документацию нужной программы.
2. Выбрать свою операционную систему или среду.
3. Выполнить указанную там команду установки.
4. Проверить результат с помощью `command -v` или команды показа версии из документации.

## Бонус: права доступа

Этот раздел не обязателен для основного сценария. Его можно разобрать, если останется время.

В подробном выводе `ls -l` в начале строки видны тип объекта и права доступа:

```bash
ls -l
```

Пример фрагмента вывода:

```text
-rwxr-xr-x 1 user group 42 Aug 10 12:00 script.sh
```

Первая позиция `-` означает обычный файл. Следующие девять символов разбиты на три группы:

1. права владельца;
2. права группы;
3. права остальных пользователей.

Обозначения прав:

- `r` — read, чтение;
- `w` — write, изменение;
- `x` — execute, выполнение;
- `-` — соответствующего права нет.

В примере владелец имеет права `rwx`, а группа и остальные пользователи — `r-x`.

`chmod` изменяет права. Дать файлу право на выполнение можно так:

```bash
chmod +x script.sh
```

После этого shell сможет запускать файл как исполняемый, если его содержимое и среда подходят для запуска.

Можно встретить и числовую запись:

```bash
chmod 755 script.sh
```

Здесь `755` означает `rwx` для владельца и `r-x` для группы и остальных. На первом знакомстве достаточно узнавать такую форму — вычислять числовые права не требуется.

`chown` изменяет владельца файла:

```bash
chown user file.txt
```

Вместо `user` указывают настоящее имя пользователя. Для смены владельца часто нужны права администратора. В Git Bash возможности `chmod` и `chown` могут отличаться от Linux, WSL и macOS из-за модели прав Windows.

Практическая ситуация: при запуске `script.sh` появилась ошибка `Permission denied`. Какой командой дать этому файлу право на выполнение?
