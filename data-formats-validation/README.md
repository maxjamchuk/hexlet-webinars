# Основы работы с данными: форматы, валидация и качество данных

## О воркшопе

Общий воркшоп для студентов backend, frontend, DevOps, аналитики и других
направлений начального/среднего уровня. Python используется только как средство
запуска компактных примеров; изучение языка не является темой занятия.

Основная модель:

```text
синтаксис → схема → бизнес-правила → качество данных
```

Полный путь от файла до решения:

```text
формат → parsing → structural/schema validation → business rules → data quality
       → accept / normalize / reject / quarantine
```

Успешный parsing ещё не означает корректность данных. Соответствие схеме ещё
не означает соответствие бизнес-правилам или хорошее качество данных.
Преподаватель открывает готовый файл, показывает короткий фрагмент, запускает
команду и обсуждает результат. Дописывать существенный код на занятии не нужно.

## Подготовка

Из корня репозитория:

```bash
cd data-formats-validation
uv sync --locked
```

Все команды ниже выполняются из `data-formats-validation`. Пути к данным внутри
модулей вычисляются относительно самих файлов Python через `pathlib.Path`.
`uv.lock` фиксирует зависимости: `jsonschema` для JSON Schema и `pytest` в группе
`dev` для проверок. Остальные операции используют стандартную библиотеку.

После установки примеры и тесты работают офлайн, без внешних сервисов и настройки
переменных окружения. Для явной проверки офлайн-запуска можно выполнить
`uv run --offline python tools/smoke_check.py`. Ожидаемые учебные ошибки выводятся
без traceback, код завершения каждой демонстрации — `0`. Отсутствие файла или
другая техническая ошибка приводит к ненулевому коду завершения.

## Демонстрация бизнес-правил

Файл [schema-valid-business-invalid.json](data/json/schema-valid-business-invalid.json)
с `age = 250` намеренно проходит [JSON Schema](schemas/user.schema.json).
Это не ошибка fixture: в схеме возраст — целое число от нуля без верхней границы.
Все пять полей обязательны, имя непустое, email проверяется только как строка.
Используется Draft 2020-12. Все ошибки объекта собираются через `iter_errors()`
и сортируются по пути поля.

```text
schema-valid != business-valid
```

В примере качества данных возраст ограничен диапазоном `0..120`. Это правило
конкретной предметной области, а не требование CSV или универсальное ограничение
JSON Schema. Возраст `250` тоже нарушил бы это правило.

## Правила качества данных и решения

[users-dirty.csv](data/csv/users-dirty.csv) содержит восемь записей. CSV parser
возвращает значения полей как строки. Дальнейшие проверки выполняются явно:

- **Completeness:** имя должно быть непустым после удаления внешних пробелов.
- **Validity:** возраст должен представлять целое число в `0..120`;
  `active` допускает только точные строки `true` и `false`.
- **Uniqueness:** повторный `id` — проблема. Первое появление занимает `id`,
  даже если в той записи есть другая ошибка. ID сравниваются как строки CSV.
- **Normalization:** внешние пробелы в имени убираются в копии записи.
  Возраст `180` не исправляется догадкой на `18`.

Номера строк включают заголовок как строку 1. В этом fixture каждая запись
занимает одну физическую строку; `row 4` — запись с `id=3`.
Строка с несколькими проблемами считается невалидной только один раз.
Maria после нормализации входит в пять валидных строк. Исходный CSV не меняется,
файлы с исправленными или отклонёнными записями не создаются.

Отчёт служит основой для обсуждения решения:

| Решение | Пример |
|---|---|
| accept | Принять запись без проблем |
| normalize | Убрать внешние пробелы в имени Maria и повторно проверить |
| reject | Отклонить повторную запись с `id=1`, если политика запрещает дубли |
| quarantine | Отложить запись с возрастом `180` или пустым именем для уточнения |

Конкретная политика зависит от системы. Demo показывает проблемы и изменения
в памяти; очередь карантина и сохранение результатов не реализуются.

## YAML и XML

Это визуальные примеры без отдельных runtime demo и без дополнительных зависимостей:

- [user.yaml](data/yaml/user.yaml) — тот же пользователь и список ролей.
- [service-config.yaml](data/yaml/service-config.yaml) — небольшая конфигурация сервиса.
- [broken-indentation.yaml](data/yaml/broken-indentation.yaml) — намеренно неверный
  отступ у `port`: он ошибочно вложен под строковое значение `name`.
- [user.xml](data/xml/user.xml) — тот же пользователь в XML.
- [user.xsd](schemas/user.xsd) — компактная схема XML с типами полей.

XSD иллюстрирует механизм схем и не запускается в основном маршруте.
Ссылки `$schema` и `xmlns:xs` обозначают стандарт схемы и пространство имён;
демонстрации не выполняют по ним сетевые запросы.

## Тесты

```bash
uv run pytest -q
```

Тесты поддерживают воспроизводимость: проверяют fixtures, сообщения демонстраций,
порядок ошибок, граничные значения, уникальность и сохранность исходных данных.
Они не являются учебным материалом занятия.

## Smoke-check

```bash
uv run python tools/smoke_check.py
```

Последовательно запускает четыре demo текущим интерпретатором, проверяет коды
завершения и ключевые строки stdout, затем запускает pytest. При ошибке показывает
название проверки, stdout/stderr команды и завершается ненулевым кодом.
Успешный результат:

```text
json_parsing: OK
json_schema_validation: OK
csv_parsing: OK
data_quality: OK
pytest: OK

Smoke check passed.
```

## Ожидаемый вывод

### JSON parsing

```text
valid-user.json: OK
invalid-syntax.json: PARSE ERROR at line 4, column 17
```

Trailing comma в `invalid-syntax.json` намеренная. Здесь приведён результат Python
3.13.2. Координаты берутся из `JSONDecodeError`: в Python 3.12 сообщение может
указывать на закрывающую скобку (`line 5, column 1`), а в 3.13 — на запятую.
Координаты также изменятся, если переместить ошибку в файле.

### JSON Schema

```text
valid-user.json: VALID

invalid-user.json: INVALID
  - age: expected integer
  - name: must not be empty

schema-valid-business-invalid.json: VALID
```

### CSV parsing

```text
Input:
42,"Smith, John",27

split(',') -> 4 pieces
42 | "Smith |  John" | 27

csv.reader -> 3 fields
42 | Smith, John | 27
```

У CSV есть правила quoting/escaping, поэтому его нужно читать CSV parser'ом.

### Data quality

```text
Rows: 8

Problems:
- row 4: missing name
- row 5: age 180 is outside 0..120
- row 6: duplicate id=1

Normalizations:
- row 7: name "  Maria  " -> "Maria"

Valid rows: 5
Invalid rows: 3
```
