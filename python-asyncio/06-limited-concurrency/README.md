# Стадия 06: ограниченная конкурентность

## Что показывает пример

Можно создать много конкурентных операций, но пропускать в участок с реальным I/O не более трёх одновременно. `asyncio.Semaphore` помогает контролировать нагрузку на удалённый сервис и пул соединений.

## Файлы

Рекомендуемый порядок:

1. `mock_server.py` — самостоятельная копия многопоточного локального сервера;
2. `main.py` — десять запросов с `MAX_CONCURRENCY = 3`.

## Запуск

```bash
# Терминал 1
uv sync
uv run python mock_server.py
```

```bash
# Терминал 2
uv run python main.py
```

После проверки остановите сервер сочетанием `Ctrl+C`.

## Что наблюдать

Все десять корутин передаются в `asyncio.gather()`, но сообщения о начале и завершении появляются группами примерно по три. Семафор ограничивает только участок с `client.get()`. Ограниченная конкурентность не равна последовательному выполнению: задача семафора — контроль нагрузки, а не максимальная скорость любой ценой.

## Ожидаемый результат

Десять запросов с секундной задержкой проходят четырьмя группами: `ceil(10 / 3)`, поэтому общее время составляет примерно 4 секунды и может немного отличаться. Без mock-сервера выводится короткая подсказка без traceback.
