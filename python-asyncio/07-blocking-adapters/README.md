# Стадия 07: блокирующий код и адаптеры

## Что показывает пример

`async def` не превращает блокирующую функцию в неблокирующую. Три максимально похожих сценария показывают остановку event loop, нормальное асинхронное ожидание и адаптацию существующей блокирующей I/O-функции через `asyncio.to_thread()`.

## Файлы

Рекомендуемый порядок запуска:

1. `blocking_demo.py` — `time.sleep(2.0)` внутри `async def`;
2. `non_blocking_demo.py` — `await asyncio.sleep(2.0)`;
3. `to_thread_demo.py` — синхронная `load_report()` выполняется через `asyncio.to_thread()`.

Во всех файлах heartbeat пытается печатать сообщение каждые 0.5 секунды.

## Запуск

```bash
uv sync
uv run python blocking_demo.py
uv run python non_blocking_demo.py
uv run python to_thread_demo.py
```

## Что наблюдать

В первом примере heartbeat не получает управление во время `time.sleep()`. Во втором он продолжает работать во время `await`. В третьем блокирующий I/O уходит в отдельный поток, поэтому event loop также остаётся свободен.

`to_thread()` — адаптер для существующей блокирующей I/O-функции. Он не означает, что любая CPU-bound задача станет выполняться эффективно: для тяжёлых вычислений обычно рассматривают процессы или специализированные инструменты.

## Ожидаемый результат

В `blocking_demo.py` первая отметка heartbeat появляется только примерно на второй секунде. В остальных двух примерах отметки идут примерно каждые 0.5 секунды, в том числе во время двухсекундного ожидания. Время может немного отличаться.
