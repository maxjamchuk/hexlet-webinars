# Стадия 05: реальные HTTP-запросы

## Что показывает пример

Искусственное ожидание заменяется запросами к локальному HTTP-серверу. Один `httpx.AsyncClient` переиспользуется для группы конкурентных запросов, а `response.raise_for_status()` отделяет успешные ответы от HTTP-ошибок.

## Файлы

Рекомендуемый порядок:

1. `mock_server.py` — многопоточный локальный сервер на стандартной библиотеке;
2. `main.py` — три успешных запроса через `asyncio.gather()`;
3. `errors_demo.py` — ответы `200`, `503` и клиентский таймаут.

`ThreadingHTTPServer` обслуживает запросы в разных потоках, поэтому сам сервер не превращает конкурентный клиентский пример в последовательный.

## Запуск

```bash
# Терминал 1
uv sync
uv run python mock_server.py
```

```bash
# Терминал 2
uv run python main.py
uv run python errors_demo.py
```

После демонстрации остановите сервер в первом терминале сочетанием `Ctrl+C`.

## Что наблюдать

В `main.py` запросы завершаются в порядке задержек, но результаты `gather` сохраняют исходный порядок. В `errors_demo.py` ошибка каждого запроса превращается в понятный строковый результат, поэтому `503` не отменяет ожидание остальных проверок. Запрос `reports` превышает таймаут около двух секунд.

## Ожидаемый результат

Успешный сценарий возвращает три `OK` примерно за 3 секунды. Сценарий ошибок выводит `auth: OK`, `billing: HTTP 503`, `reports: timeout`. Время может немного отличаться. Без mock-сервера клиент завершается с ненулевым кодом и подсказкой, но без большого traceback.

## Вопрос для самопроверки

Почему три HTTP-запроса выполняются примерно за максимальную, а не суммарную задержку?
